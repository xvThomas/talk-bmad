# Decision Log

## 2026-09-05 - Scope

- Decision: Deliver confirmed post-response token observability only.
- Rationale: Provider usage is already available in backend domain data; preflight estimation and context reduction are deferred.

## 2026-09-05 - Output Limits

- Decision: Separate provider output capability from Talk's requested output ceiling.
- Rationale: The existing `MaxOutputTokens` value is applied to Anthropic but ignored by the OpenAI-compatible client and does not consistently represent provider limits.

## 2026-09-05 - Transport

- Decision: Send usage through a custom AG-UI SSE event after every completed LLM response.
- Rationale: A user turn can include multiple LLM calls due to tool execution; a custom event avoids a new endpoint.

## 2026-09-14 - Stream-only total, no persistence

- Decision: The backend does NOT persist usage. Session cumulative consumption is fed exclusively by a `turn_usage` event emitted at the end of each turn, never by summing individual `token_usage` events in the frontend.
- Rationale: The cumulative is session-scoped current consumption, reset on conversation load and page reload. Persisting usage would serve historical analytics, which is out of scope.

## 2026-09-16 - Provider-normalized total tokens

- Decision: Each LLM client calculates `total_tokens` using provider-specific accounting and carries it through `domain.Usage` into `token_usage` and `turn_usage`.
- Rationale: OpenAI cache/reasoning values are subsets of input/output, while Anthropic cache-read/cache-creation inputs are separate. A frontend formula would either double-count OpenAI or undercount Anthropic.

## 2026-09-16 - Total-token formulas

- Decision: OpenAI-compatible total is `input + output`; Anthropic total is `input + cache_read + cache_write + output`.
- Rationale: These formulas follow the providers' current response accounting and yield a provider-neutral processed-volume value without double counting.

## 2026-09-16 - Anthropic reasoning breakdown

- Decision: Keep reasoning optional and create a separate backend story to capture Anthropic thinking-token details only from a documented provider field.
- Rationale: The pinned Anthropic SDK currently exposes thinking content and aggregate output but no typed thinking-token count. Estimation would be misleading; thinking must not be added again to output or normalized total.
