# Decision Log

## 2026-09-05 - Scope

- Decision: Deliver confirmed post-response token observability only.
- Rationale: Provider usage is already available in backend domain data; preflight estimation and context reduction are deferred.

## 2026-09-05 - Output Limits

- Decision: Separate provider output capability from Talk's requested output ceiling.
- Rationale: The existing `MaxOutputTokens` value is applied to Anthropic but ignored by the OpenAI-compatible client and does not consistently represent provider limits.

## 2026-09-05 - Transport

- Decision: Send usage through a custom AG-UI SSE event after every completed LLM response.
- Rationale: A user turn can include multiple LLM calls due to tool execution; a custom event avoids a new endpoint.

## 2026-09-14 - Stream-only total, no persistence

- Decision: The backend does NOT persist usage. The session cumulative consumption displayed by the frontend is fed exclusively by a `turn_usage` event emitted at the end of each turn (carrying `TurnEvent.TotalUsage`), never by summing individual `token_usage` per-call events.
- Rationale: The cumulative is a session-scoped "current consumption" indicator reset on conversation load and page reload. There is no durable value to preserve. A `turn_usage` missed on a dropped stream self-heals at the next reload. Persisting usage would serve a historical analytics need, which is out of scope (PRD §6).
