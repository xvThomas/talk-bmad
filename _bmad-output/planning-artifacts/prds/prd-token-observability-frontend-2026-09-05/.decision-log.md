# Decision Log

## 2026-09-05 - Primary Visualization

- Decision: Use a compact horizontal context progress indicator near the model selector.
- Rationale: It supports exact counts, percentages, and status scanning in a dense chat control area.

## 2026-09-05 - Update Frequency

- Decision: Update the display after every completed LLM response event.
- Rationale: Tool loops can produce multiple LLM responses in one user turn; this also preserves confirmed data before a later error interrupts the turn.

## 2026-09-05 - Scope

- Decision: Label all displayed metrics as the last completed call and avoid pre-send estimation.
- Rationale: The first release must not represent confirmed provider usage as a prediction of the next request.
