# Decision Log

## 2026-09-05 - Primary Visualization

- Decision: Use a compact horizontal context progress indicator near the model selector.
- Rationale: It supports exact counts, percentages, and status scanning in a dense chat control area.

## 2026-09-05 - Update Frequency (superseded 2026-09-16)

- Original decision: Update the display after every completed LLM response event.
- Original rationale: Tool loops can produce multiple LLM responses in one user turn.
- Superseded because: UI review showed that per-call replacement causes difficult-to-read context movement during a tool turn.

## 2026-09-05 - Scope

- Decision: Avoid pre-send estimation and label confirmed usage by its actual scope.
- Rationale: Confirmed provider usage must not be represented as a prediction of the next request.

## 2026-09-16 - End-of-turn publication

- Decision: Buffer the latest valid `token_usage` and publish it only when `turn_usage` closes the complete or interrupted turn.
- Rationale: This preserves the correct final-call context ratio while providing a stable, once-per-turn UI update.

## 2026-09-16 - Remove compact output ratio

- Decision: Remove the compact `out` / `output_ratio` display; keep available output counts in details.
- Rationale: The final call's output ratio is not representative of a multi-call turn's peak or authoritative total.

## 2026-09-16 - Normalized session consumption

- Decision: Display backend-normalized cumulative `total_tokens` immediately before `ctx`, once confirmed.
- Rationale: Provider cache accounting differs, so only the backend LLM client can normalize totals reliably. The frontend must sum `turn_usage.total_tokens`, not reconstruct it.

## 2026-09-16 - Optional reasoning details

- Decision: Keep `reasoning_tokens` optional and omit it when unavailable.
- Rationale: OpenAI exposes a reasoning breakdown included in output totals; the pinned Anthropic SDK currently exposes output totals but not a typed thinking-token breakdown.
